# Обновление 1.2.0

## Область изменений

Реализованы только согласованные пункты: разделение класса и архетипа, информационное количество настроенных явлений, настоящий уровень Wandering-черт, смысл постоянного выбора Relinquish Control, signature-данные и Spirit Familiar.

Полноценный новый процесс ежедневной подготовки, ограничения смены primary по действиям/Refocus и дополнительные проверки prerequisites Wandering не добавлялись. Существующий обработчик ночного отдыха оставлен. Это не заявление о полной RAW-автоматизации всего класса.

## Класс и архетип

- Класс определяется по Apparition Attunement / системному классу Animist. Если также есть Dedication, приоритет у класса.
- Dedication создаёт отдельную подготавливаемую сакральную запись на Мудрости: два слота заговоров, без ранговых слотов и без автоматических Сосудов.
- Заговор явления добавляется в книгу, но не занимает слот автоматически. Второй заговор и подготовку выбирает игрок обычным интерфейсом PF2e.
- Basic / Expert / Master Animist Spellcasting определяют стандартные архетипные слоты и ранг владения. Учитываются как slug, так и исходный системный UUID, включая переведённые предметы.
- Apparition Magic создаёт отдельную подготавливаемую запись «Магия явления — только заклинания явления» с дополнительными слотами ниже двух старших рангов. Модуль заполняет её только заклинаниями явления. Ручная правка книги/подготовки остаётся возможной, без дополнительного блокировщика.
- Повторное открытие/привязка не сбрасывает уже израсходованную подготовку. Повышение уровня и изменение соответствующих архетипных черт пересчитывает управляемую запись.
- Неуправляемые записи других классов модуль не преобразует.

### Обновление старого персонажа с Dedication

При запуске или новой привязке старая управляемая spontaneous-запись преобразуется в prepared. Лишние управляемые ранговые заклинания и автоматические Сосуды убираются; они не положены одной Dedication. До преобразования сохраняется снимок управляемых предметов в `flags.pf2e-dailies-apparition-fix.rulesBackup120`.

Это аварийная копия исходных данных, не кнопка автоматического отката. Полная резервная копия мира перед установкой обязательна. Если раньше использовалось неправильное spontaneous-колдовство архетипа, после обновления нужно заново выбрать подготовленные заклинания. Израсходованные spontaneous-слоты невозможно однозначно превратить в конкретные израсходованные prepared-заклинания.

## Количество явлений — только текст

В менеджере показано: «Настроено явлений: N. По правилам для этого персонажа — M».

- Класс: 2 / с 7-го уровня 3 / с 15-го 4.
- Архетип: 1; подсказка о дне простоя для смены связи.
- Ни интерфейс, ни API не запрещают добавить больше. Нет всплывающего подтверждения, автоматического удаления или обрезания списка из-за количества.

## Wandering

Новая черта сравнивается с уровнем получения заменяемой по настоящему уровню, без округления к 6/12/16. Это действует и в списке, и при вызове API. Остальная существующая логика не изменялась.

## Relinquish Control

- Хранится фиксированный выбор при получении черты, а не свободный выбор каждого дня.
- Смена существующего выбора обозначена как «Переобучение / исправление выбора» и требует обычного подтверждения смысла операции; права ГМа не требуются.
- Явление можно отвязать. Профили больше не удерживают его принудительно; профиль/ремонт не восстанавливает его только из-за постоянного выбора.
- Постоянное явление не назначается основным принудительно. При явном выборе и при существующей ночной автопривязке передаётся `autoPrimary: false`.
- Исходный ночной цикл не заменён отдельной ежедневной подготовкой в этом выпуске.

## Signature spells

Классовые ранговые apparition spells имеют настоящий `system.location.signature: true`. Старые управляемые заклинания исправляются при запуске; слоты при этом не восстанавливаются. Заговоры не получают флаг для виртуальных повышенных строк. Архетип использует обычную подготовку, не классовый диалог spontaneous-каста.

Лишние виртуальные строки PF2e скрываются только в DOM/CSS управляемой классовой записи. Звёздочка ручного снятия signature не показывается; данные самого заклинания остаются корректными. Выбор старшего слота при исчерпании младших сохранён.

## Духовный фамильяр (Spirit Familiar)

Раздел появляется при наличии Spirit Familiar (системный источник или slug `spirit-familiar-animist`).

1. Выберите настроенное явление.
2. При желании выберите существующий Actor типа familiar. Можно вести состояние без Actor.
3. Сохраните связь.
4. Если фамильяр погиб/уничтожен, нажмите «Фамильяр уничтожен».
5. При следующей подготовке нажмите «Проявить при подготовке / исправить» и подтвердите подготовку либо ручное исправление.

Поведение:
- гибель не определяется автоматически по ОЗ;
- при удалении связанного Actor данным пользователем автоматически отмечается потеря фамильяра, если у пользователя есть права на персонажа;
- Actor фамильяра никогда не удаляется модулем и не создаётся заново при проявлении;
- при отвязке связанного явления фамильяр отмечается уничтоженным;
- при потере фамильяра само явление остаётся настроенным, но его управляемые заклинания, Сосуд и Lore-преимущества снимаются;
- общие преимущества сохраняются, если их предоставляет другое активное явление;
- привязка/профиль/ремонт не снимают состояние потери; проявление — отдельная явная команда;
- проявление восстанавливает преимущества, но не пополняет потраченные слоты и не назначает primary принудительно;
- смена связи — осознанный выбор при подготовке/ручное исправление с подтверждением, не новая система временных хард-локов.

Особые эффекты сторонних модулей и произвольные пользовательские Rule Elements не отслеживаются. Бонусы/штрафы, не управляемые этим модулем, при необходимости корректируются вручную.

## Проверки

- `npm test`: ESLint, Prettier, локализации и согласованность релиза.
- `BROWSER_TEST_NO_SANDBOX=1 npm run test:browser`: 75 тестов в локальном Chromium с mock-документами Foundry/PF2e. На обычном компьютере флаг отключения sandbox не требуется.
- 23 отдельных локальных теста пройдены на стенде исходного повышения с нативными методами `cast/consume` PF2e 8.6.1. Извлечённый исходный код системы в релиз не включается.

Это не интеграционное тестирование работающего мира Foundry 14.369. Обязательна проверка на копии мира: классовый анимист, Dedication без Basic, архетипы с Basic/Expert/Master и Apparition Magic, расход слотов, общий Vessel/Lore, потеря/проявление фамильяра и сохранение состояния после перезапуска.
