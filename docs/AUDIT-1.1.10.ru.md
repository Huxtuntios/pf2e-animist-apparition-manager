> Исторический отчёт версии 1.1.10. Поведение, изменённое в 1.2.0, описано в [новом отчёте](UPDATE-1.2.0.ru.md).

# Проверка версии 1.1.10

## Область проверки

Проверена рабочая ветка исправлений на основе исходного коммита `53018c5dd3f50e7030235541c572ed9c2e6606ee` (версия 1.1.7) и предыдущих исправлений 1.1.8–1.1.9. Это аудит данной копии, а не проверка любых последующих изменений в GitHub.

Целевая среда пользователя: Foundry VTT 14.369, PF2e 8.6.1. Для сверки использовались предоставленные ранее исходники клиента и PF2e из профиля. Полный экземпляр Foundry с игровым миром не запускался.

## Исправления

1. **Индекс диагностики.** Используется только листовое поле `system.traits.otherTags`, без запроса родительского `system.traits`. Это устраняет пересечение с `system.traits.value`, которое может присутствовать в базовой проекции индекса. Исправление 1.1.9, оставлявшее родительское поле, было недостаточно надёжным.
2. **Миграция PF2e Dailies.** Чужие временные предметы больше не получают флаг временных предметов этого модуля только из-за `pf2e-dailies.temporary`. Сохраняется перенос распознанных записей заклинаний, управляемых источников и временных духов. Изменение не откатывает автоматически ошибочные флаги, уже записанные предыдущими версиями: их происхождение нельзя надёжно отличить от корректных флагов.
3. **Отключённый модуль.** Миграции персонажей и очистка старого реестра Lore не запускаются при выключенной настройке модуля. Совместимый обработчик Avatar передаёт событие исходному обработчику, если модуль выключен.
4. **Vessel Spells.** Явно пустой или не полностью заполненный набор основных духов учитывается и при малом числе духов. Общий Vessel доступен, если хотя бы один предоставляющий его дух основной.
5. **Повторный рендер листа.** При повторном использовании DOM снимаются только внесённые модулем ограничения Vessel, восстанавливаются прежние disabled/title/aria-disabled и удаляется собственный блокирующий слушатель. Уже отключённая по другой причине кнопка не разблокируется. Кнопки смены основного духа не дублируются.
6. **Правило фокуса.** Число неактивных Vessel считается по уникальным предметам заклинаний, а не по числу духов, предоставляющих одинаковое заклинание. На стенде проверяется создаваемое Rule Element; реальный итоговый фокус с правилами других модулей требует проверки в мире.
7. **Привязка и отвязка.** На одном клиенте операции по одному объекту персонажа выполняются последовательно. Повторные нажатия больше не создают параллельные копии духа и его заклинаний.
8. **Повторяющиеся ссылки.** Список UUID заклинаний из описания дедуплицируется; старый синтаксис `@Compendium[...]` распознаётся без учёта регистра.
9. **Профили, вчерашний набор и восстановление.** Ошибка разрешения отдельного UUID учитывается как отсутствующий источник, а не прерывает весь проход исключением.
10. **Wandering Feats.** Неизменённое описание при редактировании сохраняет исходные HTML и ссылки. Изменённый текст экранируется. Сохранение мировых способностей ограничено GM; дробный уровень приводится к целому.
11. **Импорт собственных духов.** Убрано повторное применение сырого `vessel.source.system` после нормализации. Оно отменяло обязательные признаки focus/animist и поля формы. Остальные данные исходного заклинания, включая урон, по-прежнему переносятся при создании.
12. **Кэш списков.** Частичный сбой загрузки компендиума больше не кэшируется до перезагрузки клиента навсегда. Следующее открытие повторяет загрузку.

Ранее добавленная возможность тратить доступные слоты более высокого ранга сохранена.

## Проверки и результаты

- `npm test`: ESLint, Prettier, языковые файлы (250 ключей в каждом языке), структура релиза — успешно.
- `npm run test:browser`: **45 успешно, 0 ошибок**. Настоящий DOM Chromium; документы, разрешения, диалоги, коллекции и окружение Foundry имитируются.
- Отдельный локальный набор каста: **23 успешно, 0 ошибок**. Проверялись доступность более высокого ранга, расход выбранного слота, отсутствие бесплатного каста, отмена диалога, исчерпание слота при открытом диалоге, повторный рендер и изоляция от других списков. Использовались локально извлечённые методы cast/consume PF2e 8.6.1; этот сторонний тестовый исходник не включён в репозиторий или релиз.
- Сборка `v1.1.10`: ZIP из 15 файлов, CRC и версия/ссылки итогового манифеста проверены. Тесты и инструменты разработки не входят в устанавливаемый модуль.
- Набор регрессии запускался также на предыдущей сборке 1.1.9: среди первых 40 тестов 19 падали. Это подтверждает, что соответствующие тесты обнаруживают старое поведение, а не только импортируют файлы.

## Как повторить включённые тесты

```sh
npm ci
npm test
npm run test:browser
npm run build:release -- --repo Huxtuntios/pf2e-animist-apparition-manager --tag v1.1.10
```

Для `test:browser` нужен установленный Chrome/Chromium. Если исполняемый файл не найден в PATH, задайте `CHROME_BIN`. Пример PowerShell:

```powershell
$env:CHROME_BIN = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:browser
```

Можно также запустить HTTP-сервер в корне репозитория и открыть `tests/audit.html`. Страница автономно создаёт тестовое окружение; её не следует открывать внутри игрового клиента Foundry. Запуск через `file://` не подходит для импорта ES-модулей.

`npm test` не запускает браузер автоматически; для браузерных регрессий используется отдельная команда.

## Ограничения и оставшиеся риски

- Нельзя гарантировать «работает абсолютно всё» без проверки реального мира, сервера Foundry, встроенных схем и Rule Elements.
- PF2e Dailies и PF2e Avatars не запускались как реальные установленные модули. Изоляция Dailies проверялась на имитации флагов; совместимость Avatars с конкретной версией требует отдельного теста.
- Очередь привязки действует на одном клиенте. Одновременные действия GM и игрока с разных клиентов, а также пересечение подготовки с ночным отдыхом не являются распределённой транзакцией.
- Многошаговые изменения предметов не атомарны: при обрыве связи или отказе серверной операции могут остаться частично выполненные изменения. Нужна резервная копия мира.
- Предпосылки Wandering Feats, кроме поддерживаемых требований к духам, по-прежнему не проверяются автоматически; это существующее ограничение, не исправленное данным выпуском. Также сохранено существующее округление уровней нестандартных wandering feats к стандартным категориям.
- Парсер ожидает структуру описания духа, используемую системой/редактором модуля. Произвольный вручную изменённый HTML может потребовать правки.
- Сохранён диапазон совместимости манифеста, но V13 и другие версии PF2e не проверялись.

## Приёмка в тестовом мире

Перед обновлением сохраните копию мира. После установки перезапустите сервер и обновите все клиенты.

1. Открыть диагностику и список духов: нет ошибки про `otherTags`.
2. Привязать два духа с общим заклинанием; повторно нажать привязку. Копия заклинания одна. Отвязать первого — общее заклинание остаётся; отвязать последнего — удаляется только управляемое заклинание.
3. Исчерпать слоты 2-го ранга, оставить один слот 3-го. Заклинание доступно, тратится слот 3-го ранга. После расхода последнего подходящего слота становится недоступно.
4. Сменить основной дух, снять выбор основного, повторить на листе игрока и GM. Проверить доступность Vessel и фактический максимум фокуса. Отдельно проверить Medium и Circle of Spirits.
5. Сохранить/применить профиль, восстановить вчерашний набор и выполнить ремонт. Проверить предупреждения об удалённых источниках.
6. Создать, изменить, экспортировать и импортировать собственного духа с уроном и спасброском у Vessel. Проверить бросок и расход фокуса.
7. Отредактировать только название собственного Wandering Feat с форматированным описанием, затем заменить feat на персонаже. Проверить место, level.taken, предоставляющую способность и её itemGrants в реальной PF2e.
8. Выполнить ночной отдых: временные духи и их управляемый контент очищаются; посторонние предметы не удаляются этим модулем. С включённым Dailies проверить и его собственные подготовки.
9. Повторить отдельными наборами: без Dailies/Avatars, с Dailies, затем с Avatars. Проверить Avatar, Relinquish Control и постоянного духа.
