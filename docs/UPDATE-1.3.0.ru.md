# 1.3.0 — интерфейс и загрузка менеджера

## Что изменено

- Три вкладки: **Явления**, **Способности**, **Профили**.
- Сначала показываются данные персонажа: настроенные явления, основные, количество по правилам и фокус. Подготовка этого экрана не ждёт компендиумов или `fromUuid`.
- Каталог загружается отдельно. На первом проходе индексируются названия, изображения, Знания и ссылки из описания; полные документы всех заклинаний заранее не запрашиваются.
- Заклинания и сосуд запрашиваются только при раскрытии конкретного явления. Успешные результаты кешируются в пределах клиентской сессии; параллельные обращения к одному UUID объединяются. Одновременно выполняется не более шести UUID-запросов менеджера.
- Странствующие черты загружаются при открытии вкладки «Способности», независимо от каталога.
- Предпросмотр разрешает неизвестные источники только выбранного профиля, а не всех сохранённых профилей. Он не применяет профиль и не меняет персонажа.
- Локальные ошибки и кнопки «Повторить»: недоступный источник не блокирует остальное меню. Успешно загруженные данные остаются видны.
- Сохраняются вкладка, поиск, раскрытые карточки, черновики полей, выбранный профиль, прокрутка и изменённый размер окна. Состояние хранится на клиенте в памяти, для данного Actor; после обновления страницы сбрасывается.
- Дополнительные инструменты — ручной максимум фокуса, автоматический выбор основных, диагностика и очистка — находятся в сворачиваемом блоке внизу.
- Адаптивная компоновка: две колонки на широком окне, одна колонка на узком; светлая/тёмная тема, клавиатурное переключение вкладок, нативные кнопки.
- Значки основного, постоянного явления и потери преимуществ фамильяра имеют отдельные текстовые подписи.
- Уточнены подсказки профилей и настоящего уровня странствующих черт.

## Правила и данные

Количество настроенных явлений — **только информация**, не ограничение. Кнопки привязки не блокируются при превышении нормы.

Основной файл механик `apparition-fix.mjs` не изменён относительно 1.2.0: разделение класса/архетипа, signature spells, Relinquish Control, Spirit Familiar и каст с повышением сохраняются. В Wandering изменена загрузка и сброс кеша, не правила замены. Просмотр интерфейса сам по себе не записывает флаги/предметы Actor. Запись происходит при явном действии: привязке, смене основного, применении профиля и т. п.

## Диагностика загрузки

В дополнительных инструментах откройте «Диагностика»: в отчёт добавлены времена первого показа, последней подготовки интерфейса и загруженных разделов.

Либо выберите токен персонажа, откройте менеджер и выполните в консоли:

```js
const actor = canvas.tokens?.controlled[0]?.actor ?? game.user.character;
console.log(game.modules.get("pf2e-dailies-apparition-fix").api.getManagerPerformance(actor));
```

Отчёт содержит `firstRenderMs`, `lastContextMs`, `catalog`, `wandering`, `profile`, `detailLoads`. После закрытия окна доступен последний отчёт для того же Actor. Если менеджер ещё не открывался, возвращается `null`.

Это наблюдения клиента, **не контролируемый бенчмарк**. Первый показ не включает отложенную загрузку разделов. Величина ускорения зависит от компендиумов, кеша, сети и количества источников; фиксированный коэффициент не заявляется.

Запросы имеют 12-секундный срок ожидания интерфейса. Это **не отмена** запроса Foundry. При зависшем транспорте повтор не гарантирует восстановления; если все запросы зависли, может понадобиться обновление клиента. Ограничение параллелизма учитывает фактически незавершённые запросы, чтобы повторы не создавали неограниченную нагрузку.

## Проверки

- `npm test`: ESLint, форматирование, соответствие EN/RU и проверка релизной структуры.
- `npm run test:browser`: 97 проверок Chromium с подменёнными документами Foundry/PF2e; в том числе реальный Handlebars-шаблон, DOM и обработчики, холодный каталог, отложенные детали, кеширование, ограничение параллелизма, таймауты, частичные ошибки, повторы, гонки обновления профиля, закрытие окна, отсутствие записей при просмотре и отсутствие лимита привязки.
- Отдельный изолированный стенд: 23 проверки нативного пути каста/списания слотов с извлечёнными методами PF2e; 23/23 пройдено. Это не полноценный клиент Foundry.
- Проверены установочный ZIP и совпадение исходников внутри него.
- Визуально проверены светлая/тёмная тема, широкий экран, ширина 390 px, раскрытые заклинания, профили, способности, загрузка, ошибка и дополнительные инструменты.

Это **не запуск полноценного мира Foundry 14.369 / PF2e 8.6.1**. Окончательная проверка реальной скорости, интеграций и стилей системы нужна в копии вашего мира.

## Установка готового модуля

1. Сделайте резервную копию мира.
2. Остановите Foundry. Замените содержимое папки `Data/modules/pf2e-dailies-apparition-fix` файлами из установочного ZIP. `module.json` должен находиться непосредственно в этой папке.
3. Запустите Foundry и обновите браузер клиента с очисткой кеша (Ctrl+F5).
4. Проверьте менеджер на персонаже класса и архетипа: привязку, смену основного, переходы между вкладками, профили и фамильяра.

Не устанавливайте вторую копию под другим ID.

## Исходники для GitHub Desktop

1. Распакуйте архив исходников отдельно.
2. Скопируйте **содержимое** папки `pf2e-animist-apparition-manager` в корень локального репозитория. Не заменяйте и не удаляйте его `.git`.
3. В GitHub Desktop проверьте изменения, сделайте Commit и Push.
4. Для публикации установочного релиза создайте GitHub Release с тегом `v1.3.0`: существующий workflow соберёт и приложит `module.json` и `module.zip`.

В манифесте уже указан будущий адрес релиза `v1.3.0`; до его публикации этот адрес не является доступной загрузкой. Данный пакет ничего не публикует автоматически.

Для локальных проверок исходников:

```sh
npm ci
npm test
npm run test:browser
npm run build:release -- --repo Huxtuntios/pf2e-animist-apparition-manager
```

Для браузерных тестов нужен установленный Chrome/Chromium (`CHROME_BIN` позволяет указать путь). Handlebars — только зависимость тестов; в установочный ZIP он не входит. В контейнере без поддержки sandbox используется явный параметр `BROWSER_TEST_NO_SANDBOX=1`; для обычного компьютера отключать sandbox не требуется.
